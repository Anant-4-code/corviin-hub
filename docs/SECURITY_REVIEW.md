## 1. Authentication Model & Limitations (Mandatory Notice)

> [!CAUTION]
> **CRITICAL ARCHITECTURE DISCLOSURE:**  
> CORVIIN HUB currently implements an **acting-profile selector** designed for trusted internal prototype use and multi-persona evaluation (Anant, Rohit, Utkarsh).  
> **This is NOT identity-verified authentication.**  
> Selecting a profile does not cryptographically prove user identity.

### Production Authentication Roadmap (Required Before Public / Production Launch)
Before exposing CORVIIN HUB beyond trusted internal networks or loading sensitive customer data:
1. Implement real OAuth 2.0 / OIDC (e.g., Supabase Auth, Auth0, or WorkOS).
2. Issue cryptographically signed, short-lived JWTs with server-side validation.
3. Enforce secure HTTP-only cookies or bearer authorization headers with refresh token rotation.
4. Integrate multi-factor authentication (MFA) and session revocation webhooks.
5. Store user passwords with Argon2id or bcrypt (managed by auth provider).

## 2. Backend Security & Authorization

| Security Control | Implementation Mechanism | Status | Evidence |
|---|---|:---:|---|
| **DTO Validation** | NestJS `ValidationPipe` with `class-validator` (`whitelist: true`, `forbidNonWhitelisted: true`) | **PASS** | Unknown properties are stripped; malformed payloads return HTTP 400 Bad Request. |
| **Workspace Tenant Isolation** | Strict header resolution (`x-workspace-id`) enforced in every service query | **PASS** | Every Prisma query filters by `workspaceId`. Cross-workspace attempts throw `ForbiddenException` (HTTP 403) or `NotFoundException` (HTTP 404). Verified in `api-cross-workspace.spec.ts`. |
| **Parameterized Database Queries** | Prisma ORM with native parameterized queries | **PASS** | Zero raw SQL string concatenation. All SQL execution is generated by Prisma engine using parameter substitution. |
| **Error Handling & Information Disclosure** | Global NestJS `HttpExceptionFilter` with sanitized error responses | **PASS** | Internal exception stack traces are logged server-side only and never leaked to API clients. |
| **CORS Policy** | Restricted origin whitelist in `main.ts` | **PASS** | Only authorized development and production origins (`http://localhost:5173`, `http://localhost:3001`, `capacitor://localhost`) are permitted. |

## 3. Storage Security & Object Protection

| Storage Control | Implementation Mechanism | Status | Evidence |
|---|---|:---:|---|
| **Private Cloudflare R2 Storage** | Private bucket without public read access; backend S3 client with short-lived presigned URLs | **PASS** | Bucket credentials (`R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`) are kept strictly on the backend. Client accesses files exclusively via 900-second presigned URLs. |
| **Tenant Storage Key Namespacing** | Isolated paths: `workspaces/{workspaceId}/assets/{uniqueId}_{sanitizedName}` | **PASS** | `StorageService.sanitizeFileName` removes path traversal sequences (`..`, `/`, `\`); objects cannot escape workspace boundaries. |
| **MIME & Extension Security** | Whitelist authorized formats; reject executable extensions | **PASS** | Blacklist blocks `.exe`, `.bat`, `.cmd`, `.sh`, `.php`, `.dll`, `.msi`, `.scr`, `.jar`. Executable uploads rejected with HTTP 400. |
| **Audit Trail Token Redaction** | Sanitization engine strips tokens, keys, and presigned URLs | **PASS** | `NotificationsService.sanitizeAuditValues` scrubs keys matching `/token|secret|password|accesskey|auth|presigned|credential/i` and URLs containing signatures to `[REDACTED]`. |
